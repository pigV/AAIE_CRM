# 本机申请文档识别第一阶段验证

用户于本轮确认本机处理方案和第一阶段独立验证，并授权追加本机处理规则。

目标：比较 Docling 页面结构 + Apple Vision OCR + 两个 MLX 本地量化语言模型对 Offer、CAAW、CoE、相关确认信字段的提取结果。主要修复学校角色误认、完整名称截断和课程/福利日期错配。

方案比较：继续正则仅能覆盖固定模板；纯视觉大模型的依据与资源成本难控制。本阶段选取结构保留、语义提取和原文证据校验组合；尚未承诺最终模型或准确率。

环境：M4 Pro，24 GiB。独立虚拟环境、模型与数据放本工作目录 STAGING_DATA。安装/模型预下载阶段可以联网但不读取学生文件；处理阶段用 OS sandbox 禁止网络，并使用固定本地模型目录和离线环境。

第一阶段仅运行命令行原型，不接 CRM、不更改生产代码/数据/服务/数据库，不提交推送。采用现有少量原件建立可重复的小样本验证，不将它冒充正式盲测。后续正式验收目标30–50份不同模板，约三分之一盲测；已填字段准确率≥99%、应提取字段覆盖率≥95%、关键角色/日期错配零为目标而非现有承诺。

字段输出需要值、原文片段、证据块ID、页码和坐标。证据验证不等同语义正确率；结果仍须人工核对，缺失或冲突不猜测。学校全称不得截断，Provider和host school分别保存，多段课程分别提取。

资源：单进程串行测试，分别运行模型，每次有时间和输出上限，测量耗时和峰值内存。不启动监听服务。模型不可执行任意下载仓库代码。
