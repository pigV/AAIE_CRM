# 全系统业务变更同步 Implementation Plan（实施中）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立统一、可恢复且覆盖全系统入口的业务变更机制，使材料和业务更新同步反映在工作流、状态、列表和仪表盘。

**Architecture:** 模块命令负责源事实和规则；同事务可靠记录变更与版本；共享调度按依赖重算，页面按权威快照更新。核心状态采用事务内/读取时判定，耗时任务采用可见、可重试的异步处理。

**Tech Stack:** 沿用Python、SQLite、原生JavaScript及现有测试设施；优先不引入外部消息中间件。

**Spec:** ../specs/2026-11-19-system-business-change-design.md

## Global Constraints
- 此计划替代Visa专项方案；已获全系统范围及隔离测试库5张表迁移授权，正在独立worktree实施。生产未启用。
- 所有业务确认、权限、人工覆盖、财务锁定及精确归属约束保留。
- 持久化事件若需schema迁移，先评审准确结构与迁移/兼容/回滚方案，取得授权后执行。
- 所有开发/测试在独立worktree与隔离staging；数据修复、发布/重启、GitHub提交推送遵守本次适用授权。

## Review Focus
- 不同事务所有者/嵌套savepoint：只有外层事实成功提交，事件才可被看到。
- 进程崩溃、重复、乱序：事件不丢、消费幂等、旧结果不覆盖新源版本。
- 文件已落盘但数据库失败：无“上传已完成”假成功，可追溯补偿和孤立文件。
- 证据撤销/人工覆盖/时间到期：按业务规则重算，不无条件推进阶段或抹掉人工决策。
- 全系统入口遗漏/归属改变/权限：接入表逐入口验收，旧新主体重算，前端变更版本也不能越权。

## 完成标准
