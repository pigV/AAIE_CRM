# 学生状态变化后的四处同步验收

用户已确认范围：学生详情、学生列表、首页上部统计、首页阶段分布；每次状态变化检查自动同步并截图。仅沿用本任务隔离worktree和19060/19061环境，不上线、不提交或推送。

已定位缺口：学生列表 `app.CRMHandler.students` 使用正确的共享摘要，但整页未接入自动刷新；公共快照/版本接口也无学生列表surface。旧截图验证了列表摘要函数，不等于真实打开的学生列表自动变化。

1. 使用真实完整schema和原业务结果命令复现列表快照缺失、列表筛选状态变化；检查权限、最低版本、查询条件和只读快照。
2. 为列表复用现有只读快照和刷新控制器，保留搜索/排序/阶段/顾问/日期等条件与编辑保护；通过已有workflow版本通知列表变化，不新增迁移、后台或无关模块。
3. 新建模拟学生跑主申请链路及拒签/撤回/转学/升学分支。同时打开详情、固定筛选的列表和首页；每步分别保存3张截图（首页包含上部统计及阶段分布），以实际DOM核对原生事实和API。验证筛选中退出的学生不残留；出现差异则先记录失败再最小修复。
4. 验证列表、详情和首页并发刷新不积压，运行相关业务/刷新回归。报告明确模拟数据与实际未验收边界。

本计划仅补齐用户要求的学生状态数据同步，不扩展财务、大学目录或全系统架构建设。
