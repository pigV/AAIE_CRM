## 共用机制需要实现的约束
1. 源事实、审计、命令去重、事件及主体版本在同一外层事务。Database.transaction与RevenueRepository.savepoint不能混用成两个提交点。
2. 受影响对象由业务命令验证归属，显式提供；旧新归属均需重算。共用框架不根据字符串student_id或任意SQL猜测业务。
3. 原有规则逐模块适配。需要确认的事实仍由人确认；页面统一读取权威结果，异步重算不可掩盖旧值。
4. 事件入队必须有持久化，消费至少一次并以事件/处理器版本/主体幂等，旧源版本不能覆盖新值。
5. 异步消费者与前端刷新分别验收；只有浏览器刷新正确不代表后端状态已一致。
